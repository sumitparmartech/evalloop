    Get started

    Three steps. Five minutes.

    Keep your agent as it is. Pick how you built it, copy three snippets, and you have tests that run in CI.

    01

    Install

    One package, no runtime dependencies.

    $ pip install evalloop-agents
    $ pip install "evalloop-agents[agents]"
    $ pip install "evalloop-agents[langgraph]"
    02

    Wrap and write cases

    Each case is an input plus the checks it must pass.

    # evals.py
from evalloop import Case, agent, tool
from evalloop import tool_called, grounded

@tool()
def lookup_order(order_id): ...

@agent
def support(text):
    ...  # your code, returns the answer

cases = [
  Case("track", "Where is order #1043?",
       [tool_called("lookup_order"), grounded()]),
]
    # evals.py
from agents import Agent
from evalloop import Case, tool_called, grounded
from evalloop.frameworks import openai_agents_agent

bot = Agent(name="support", tools=[lookup_order],
            instructions="...")
support = openai_agents_agent(bot)

cases = [
  Case("track", "Where is order #1043?",
       [tool_called("lookup_order"), grounded()]),
]
    # evals.py
from evalloop import Case, tool_called, grounded
from evalloop.frameworks import langgraph_agent
from my_app import graph   # compiled StateGraph

support = langgraph_agent(graph)

cases = [
  Case("track", "Where is order #1043?",
       [tool_called("lookup_order"), grounded()]),
]
    03

    Run it, then gate CI

    Five trials per case, one HTML report, exit code 1 on regressions.

    $ evalloop run evals:cases \
    --agent evals:support \
    --trials 5 --html report.html \
    --store runs --baseline last \
    --fail-on-regression

    What it catches

    Twelve ways agents fail in production.

    Each one is a check you attach to a case. Checks read the full trace, so you test what the agent did, not only what it said. Hover a card.

    Flaky runs

    Every case runs k times. A case counts as reliable only if all k pass, and flaky cases are marked.

    trials=5, pass^k
    $59.00$49.00

    Made-up numbers

    Any amount, date or id not seen in the input or a tool result fails.

    How it works

    Record. Grade. Gate the merge.

    1. 1Record the trace
    2. 2Grade it k times
    3. 3Compare with the last run
    4. 4Block the bad merge

    Record the trace

    Every model call and tool call is saved with its arguments, output, time and tokens. Use the decorators, a framework adapter, or import message logs you already have.

    from evalloop import from_openai_messages
trace = from_openai_messages(logged_messages)
trace.tool_calls   # [lookup_order(order_id="1043"), ...]

    Grade it k times

    Each case runs several trials. You get the pass rate with a 95% confidence interval, pass^k reliability, and flaky cases marked.

    refund_small_order    PASS PASS PASS FAIL PASS   80%
  FAIL grounded(numbers): 59.0 not in any source
pass rate 33%  (95% CI 19% to 51%)   reliability 0%

    Compare with the last run

    Runs are saved. A two-proportion test tells a real regression apart from bad luck, so a single unlucky trial does not block you.

    refund_small_order   100% to 40%   regressed  p = 0.01
unknown_order        80% to 60%    within noise

    Block the bad merge

    In GitHub Actions, evalloop exits with code 1, writes JUnit and a Markdown summary, and uploads the HTML report.

    Shorten the refund prompt #42 (example)

    Why I built this
    SP

    Sumit Parmar

    AI/ML and full-stack engineer, Ahmedabad

    Agents do not do the same thing twice. A test that passes once tells you very little, and most of the bugs I care about only show up on the third or fourth try. So I built the tool I wanted: run every case many times, check what the agent actually did, and stop the merge when it gets worse.

    It is open source and still young. If you ship agents, I would really like to hear what breaks for you.
